# Interview

Read relevant conversation, documents, and code before asking. Reuse established answers. Start with the problem, intended users, and observable success when those are unknown. Explore only unresolved decisions that affect behavior or implementation: workflow, data, integrations, edge cases, security, compatibility, and rollout as applicable. Do not turn a routine implementation request into a requirements interview for incidental gaps.

Ask a small batch of high-value questions at a time. Use choices when they clarify tradeoffs; otherwise use an open question. State a suggested default only when evidence supports one. Do not manufacture decisions or demand answers for irrelevant areas.

After each response, ask only necessary follow-ups. End when material requirements are clear, or when the user wants to proceed with stated assumptions. Summarize decisions and open questions. If the user also requested a spec, plan, or implementation, continue without a redundant handoff question.
